# معمارية مرصد السعودية

## المرجع المعماري

المرجع التفصيلي للبنية القابلة للتوسع هو [PROJECT_STRUCTURE.md](./PROJECT_STRUCTURE.md)، ودليل إضافة الخدمات والمصادر هو [SERVICE_INTEGRATION_GUIDE.md](./SERVICE_INTEGRATION_GUIDE.md).

## النموذج المعماري

يعتمد المرصد على فصل أربعة مفاهيم: **Service** ميزة للمستخدم، و**Provider** موقع أو جهة تزود البيانات، و**Connector/Adapter** موصل مستقل يتصل بالمزود ويحول استجابته إلى عقد موحد، و**Registry** سجل يربط الخدمات بالمصادر والمنتجات وحالات الاعتماد.

يمكن للخدمة الواحدة استخدام أكثر من مزود، ويمكن للمزود الواحد أن يغذي أكثر من خدمة. لا تتصل الواجهة بالمواقع الخارجية مباشرة.

## مسار البيانات

المزود الخارجي ← الموصل ← المحول الموحد ← فحص الجودة والترخيص ← كتالوج البيانات ← الخدمة ← واجهة العرض.

كل استجابة تحتفظ بمصدرها ومنتجها ووحداتها وتوقيتها ومنهجيتها وقيودها. لا يتم استبدال القيم المفقودة بأصفار، ولا يتم التبديل إلى مصدر احتياطي بصمت عند اختلاف الدقة أو المنهجية.

## الاعتمادية والأمان

- تعطل مصدر واحد لا يعطل بقية الخدمات.
- احترام حدود الطلب وإعادة المحاولة المتدرجة.
- تخزين مؤقت بسياسة صلاحية مناسبة لكل منتج.
- الأسرار في بيئة خادم فقط عند الحاجة، ولا تحفظ في Git أو المتصفح.
- فحص الترخيص وحقوق العرض وإعادة التوزيع قبل تفعيل أي مصدر.
- اختبارات وحدات وعقود وتكامل واختبار حي محدود منفصل.

## الوضع الحالي

- `index.html` هو مدخل الواجهة الحالي.
- أداة CHIRPS موجودة في `scripts/` والبيانات البحثية في `data/`.
- لم تُنشأ بعد كل مجلدات `src/` المستهدفة، ولم تنفذ منظومة تحميل الخدمات الديناميكية.
- الوثائق تحدد الشكل المستهدف ولا تدعي أن كل مكون منفذ.
- لا توجد قاعدة بيانات أو خدمة خلفية جديدة؛ لا تضاف إلا عند وجود حاجة عملية مثبتة.

## قواعد التغيير

أي خدمة أو موصل جديد يجب أن يمر بدليل [SERVICE_INTEGRATION_GUIDE.md](./SERVICE_INTEGRATION_GUIDE.md)، وأن يضاف باختبارات ووثائق منفصلة. لا تنفذ إعادة كتابة شاملة، ولا دمج أو نشر من فرع البحث دون اعتماد صريح.
