# معمارية مرصد السعودية

## المرجع المعماري

الوثيقة التفصيلية والمرجع الأساسي لشجرة المجلدات، وحدود المسؤوليات، وعقود البيانات، والاختبارات، والحوكمة، وخطة الانتقال المرحلي هي [PROJECT_STRUCTURE.md](./PROJECT_STRUCTURE.md).

هذه الصفحة تلخص القرارات العليا؛ عند اختلاف التفاصيل يُرجع إلى الوثيقة التفصيلية، وتُسجل القرارات الجديدة في `docs/decisions/` حتى لا تتعارض الوثائق.

## المعمارية المعتمدة

- واجهة خفيفة منفصلة عن جلب البيانات ومعالجتها.
- مجالات مستقلة: الخرائط، الطقس، الأمطار، المواقع، وكتالوج البيانات.
- محول مستقل لكل مزود بيانات، بحيث لا ترتبط الواجهة بتفاصيل المزود.
- مخططات وعقود موحدة للبيانات مع رقم إصدار ومصدر ووحدات ومنهجية وقيود.
- خطوط معالجة قابلة لإعادة التشغيل والاختبار، مع ملفات ناتجة وبيانات وصفية وبصمة.
- اختبارات وحدات وعقود وتكامل واختبارات حية محدودة.
- لا أسرار في المتصفح أو المستودع، ولا قاعدة بيانات أو خدمة مدفوعة دون حاجة مثبتة.

## الوضع الحالي

- التطبيق ما زال يعتمد على `index.html` كواجهة رئيسية؛ لا توجد حزمة بناء أو `package.json` في الفرع الحالي.
- أدوات استخراج CHIRPS موجودة في `scripts/` وتُختبر عبر Python.
- بيانات العينة في `data/chirps_daily.json`، ويجب إبقاؤها موصوفة بأنها عينة بحثية نقطية محدودة.
- ملفات CI في `.github/workflows/` للتحقق والاختبار وتحديث عينة فرع التطوير.
- لم يتم بعد نقل الواجهة إلى وحدات `src/`، ولا إضافة قاعدة بيانات أو خادم.

## مبادئ التنفيذ

1. افصل المسؤوليات دون إعادة كتابة شاملة.
2. لا تنقل ملفاً قبل معرفة كل مواضع استخدامه.
3. حافظ على سلوك التطبيق وواجهته خلال كل مرحلة.
4. نفّذ النقل على دفعات صغيرة، مع اختبارات قبل وبعد.
5. لا تعتبر وجود البيانات دليلاً على جواز إعادة نشرها.
6. لا تدمج أو تنشر من فرع البحث قبل موافقة صريحة.
