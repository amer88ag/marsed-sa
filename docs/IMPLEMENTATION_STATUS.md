# حالة التنفيذ — مرصد السعودية

آخر تحديث: 2026-11-21

## ما أصبح موجوداً في المستودع

- مستودع عام باسم `amer88ag/marsed-sa` والفرع الأساسي `main`.
- واجهة عربية RTL في `index.html`.
- خريطة تفاعلية تعتمد Leaflet وOpenStreetMap.
- اختيار 13 مدينة سعودية وتحريك المؤشر إلى إحداثياتها.
- جلب مؤشرات طقس نموذجية من Open-Meteo: الحرارة والرطوبة والهطول والرياح.
- مخطط يومي للأمطار يعرض الأيام السابقة واللاحقة المتاحة من واجهة الطقس.
- كتالوج مصادر محدث بعد مراجعة وثائق CHIRPS v3 وNASA IMERG وNCM API وGEOSA.
- عينة بيانات فعلية محفوظة في `data/chirps_daily.json` تشمل SAT وRNL لثلاثة أيام و13 مدينة، مع فحص آلي لتكامل المخطط والقيم والبيانات الوصفية.
- اختبار CI مباشر ينزّل ملفات GeoTIFF لمنتجي SAT وRNL ويتحقق من وجود قيم صالحة، ثم يرفع عينة مراجعة مؤقتة.
- إضافة الإسناد المطلوب من Open-Meteo قرب بيانات الطقس المعروضة.
- توضيح ظاهر أن قيم Open-Meteo ناتج نموذج وليست قياسات محطات رسمية.
- فرع اختبارات مستقل وطلب دمج PR #1 يضيف فحوصاً ثابتة وسير CI.
- لوحة مبدئية لسلسلة CHIRPS التاريخية للمدينة المختارة، تقرأ ملف JSON ثابتاً من فرع التطوير ولا تعرض أصفاراً عند غياب البيانات.
- سجل مركزي للخدمات في `config/services.json` وسجل لمزودي البيانات في `config/providers.json` مع حالات الخدمة والترخيص والاتصال والمنتجات.
- نواة برمجية للتحقق من السجلات ومراجع المصادر في `src/platform/registry/registry.js`.
- مركز إدارة أولي للقراءة والمراقبة في `admin/index.html` يعرض الخدمات والمصادر ويتيح البحث والتصفية؛ لا ينفذ عمليات تفعيل دائمة أو فحص اتصال حي.
- أداة Python لاستخراج قيم CHIRPS v3 DAILY SAT FINAL وDAILY RNL عند نقاط المدن الـ13 من ملفات GeoTIFF الرسمية، مع تسجيل المصدر والوحدة وتاريخ البيانات.
- اختبارات Python وNode للتحقق من نطاق التواريخ، ونمط الملفات، وإحداثيات المدن، ووصف طريقة أخذ العينات.
- مهمة Actions لاستخراج عينة تلقائية صغيرة عند تحديث أدوات الاستخراج على فرع التطوير، مع خيار تشغيل يدوي لمدد لا تتجاوز 14 يوماً. تكتب النتائج في فرع التطوير فقط.

## نتائج التحقق من المصادر

- كتالوج Google Earth Engine يصف منتج CHIRPS v3 DAILY SAT بأنه Public Domain؛ هذا لا يغني عن تحديد المنتج الفعلي وتوثيق الإسناد والمنهجية.
- CHIRPS SAT يستخدم IMERG Late V07 لتوزيع إجمالي الخماسية على أيام، وCHIRPS RNL يستخدم ERA5. لم يتم بعد ربط ملفات IMERG الخام كطبقة مستقلة.
- واجهة NCM API تتطلب بيانات دخول، وخدمة الربط المباشر مصنفة تجارية؛ لا يوجد اعتماد أو مفتاح للمشروع.
- Open-Meteo مستخدم حالياً لبيانات نموذجية فقط، ويجب مراجعة شروط الخدمة وحدود الطلب قبل الإطلاق.

## ما لم يكتمل — لا تعتبره جاهزاً للإنتاج

1. تم تحديد GEOSA مرجعاً رسمياً للحدود الإدارية، لكن شروطها واتفاقية استخدام البيانات تقيدان النسخ والتوزيع والعرض العام دون موافقة خطية؛ لذلك مُنع تضمين طبقتها قبل تصريح واضح، ويجري البحث عن بديل مفتوح.
2. لا توجد طبقة راستر لونية تاريخية على الخريطة؛ الموجود حالياً سلسلة زمنية نقطية في مخطط المدينة.
3. لا يوجد تحقق ميداني أو مقارنة مرجعية بمحطات NCM.
4. كود الاستخراج يدعم SAT وRNL ويشترط وجود قيم صالحة في كلا المنتجين. نجح اختبار المصدر الفعلي في CI لكلا المنتجين، لكن العينة ما زالت ثلاثة أيام و13 نقطة مدينة ولا تمثل تحققاً وطنياً شاملاً.
5. لا يوجد تكامل مع API المركز الوطني للأرصاد؛ يلزم اعتماد رسمي ومراجعة الشروط والتكلفة.
6. لا توجد بيانات رطوبة تربة أو NDVI أو مخزون مياه أو سيول.
7. لا توجد تنبيهات تشغيلية، ولا يجوز استخدام اللوحة الحالية للإنذار أو السلامة.
8. لم يتم بعد اختبار الأداء على أجهزة متعددة أو مراقبة توفر الخدمات الخارجية.
9. عينة CHIRPS الحالية SAT وRNL لثلاثة أيام و13 نقطة مدينة؛ لم تتم مراجعتها مقابل محطات أرضية ولا تكفي للاستنتاج المناخي.
10. يلزم توسيع فترة الاستخراج واختبار ثبات النتائج عبر فترات متعددة ومراجعتها مقابل بيانات أرضية متاحة.
11. القيم المخططة عينات أقرب خلية شبكية لإحداثيات مركز المدينة، وليست متوسطاً مكانياً للمدينة أو المحافظة.
12. نجح تشغيل CI رقم 91 في الاختبارات الوحدوية واختبار المصدر الفعلي SAT/RNL، كما نجح فحص تكامل ملف البيانات الملتزم به.

## حالة مركز إدارة الخدمات والمصادر

- المركز الحالي يعرض بيانات السجل الثابتة فقط؛ حالة الاتصال ليست فحصاً حياً إلا إذا وُصفت بذلك صراحة.
- التفعيل والتعطيل وتغيير المصدر الأساسي أو الاحتياطي لم تُفعّل بعد؛ تتطلب API خلفية ومصادقة وصلاحيات وسجل تدقيق.
- الطقس فعالة، الأمطار بحثية، الخرائط بحثية، وجودة الهواء والزلازل والمياه والغطاء النباتي والتقارير مخططة.
- تكامل NCM يتطلب موافقة واعتماداً؛ NASA IMERG يحتاج مراجعة منتج وترخيص مستقلة، واستخدامه داخل CHIRPS SAT لا يعني تكامل موصل IMERG الخام.

## قرارات تقنية

- تبقى الواجهة خفيفة وبدون قاعدة بيانات في مرحلة إثبات المفهوم.
- لا توضع مفاتيح API في المتصفح أو المستودع.
- لا تُعرض بيانات النماذج بوصفها رصداً رسمياً.
- لا تُفعّل طبقة بيانات جديدة قبل توثيق مصدرها وترخيصها ووحداتها ودقتها وتاريخ تحديثها.
- CHIRPS DAILY SAT FINAL يستخدم IMERG Late V07 لتوزيع المجاميع الخماسية على أيام؛ لا تُفسر التواريخ كنافذة رصد موحدة لمحطات القياس.
- أداة الاستخراج الحالية تنزّل ملف GeoTIFF لكل يوم على حدة وتقرأ نقاط المدن ثم تحذف الملف المؤقت؛ لا تحفظ الأرشيف العالمي في المستودع.
- مهمة استخراج البيانات محدودة بفرع التطوير ولا تنشر إلى main أو Vercel. التحديث التلقائي مقيّد بتغييرات أدوات الاستخراج والاختبارات، وتحديث ملف البيانات نفسه لا يعيد تشغيل المهمة.
- الخدمات الخارجية (Leaflet وOpenStreetMap tiles وOpen-Meteo) تعتمد على توفر مزوديها وسياساتهم وحدود الاستخدام.

## بوابة الإصدار

لا توصف النسخة بأنها «مرصد وطني مكتمل» إلا بعد اجتياز اختبارات البيانات الجغرافية، والترخيص، والتحقق من الجودة، والتغطية الوطنية، وإتاحة الخدمة ومراقبتها، ونجاح CI على GitHub.

## قيود التشغيل الحالية

ملف `data/chirps_daily.json` يحتوي عينة SAT وRNL للفترة 2026-09-01 إلى 2026-09-03 لثلاثة عشر موقعاً نقطياً. أضيفت حماية تمنع تمرير قيم nodata أو القيم السالبة أو نشر منتج فارغ بالكامل. نجح تنزيل ملفات GeoTIFF والتحقق من المنتجين في CI رقم 91، ونجحت معه اختبارات الواجهة واختبارات أداة الاستخراج وفحص تكامل ملف البيانات. هذه العينة لا تمثل متوسطات المدن ولا تحققاً ميدانياً. لم يتم تنفيذ دمج إلى main أو نشر.
