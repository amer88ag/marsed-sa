# دليل إضافة خدمة أو مصدر بيانات جديد

هذا الدليل إلزامي عند إضافة خدمة جديدة أو ربط موقع خارجي بمرصد السعودية. الهدف منع ربط الواجهة مباشرة بمواقع متعددة، وضمان أن الخدمات مستقلة وقابلة للتبديل والاختبار.

## 1. حدد ما الذي تضيفه

ميّز بين:
- **خدمة جديدة:** ميزة جديدة للمستخدم مثل جودة الهواء أو الزلازل.
- **مصدر جديد لخدمة موجودة:** موقع آخر يوفر بيانات الطقس أو الأمطار.
- **منتج جديد من مصدر معروف:** إصدار أو طبقة مختلفة من نفس الجهة.

لا تنشئ خدمة مستقلة لمجرد أن المصدر مختلف؛ قد يكون المصدر الجديد موصلاً إضافياً لخدمة موجودة.

## 2. بوابة قبول المصدر

قبل كتابة كود الاتصال، وثّق:
- الجهة المالكة والرابط الرسمي.
- المنتج والإصدار وصيغة البيانات.
- الترخيص وحقوق الاستخدام والعرض العام وإعادة التوزيع.
- التغطية الجغرافية والزمنية والدقة والتأخر.
- الوحدات والمنهجية والقيود المعروفة.
- أسلوب المصادقة وحدود الطلب والتكلفة.
- سياسة الإسناد المطلوبة.

الحالة تكون واحدة من: `approved`, `approved_with_conditions`, `research_only`, `rejected`. لا تساوِ بين كون API متاحاً وبين امتلاك حق إعادة عرض بياناته.

## 3. مكان الملفات

لإضافة موصل مصدر:
`src/providers/<domain>/<provider-id>/`

لإضافة خدمة:
`src/services/<service-id>/`

للتعريفات:
`domain/catalog/providers/<provider-id>.json`
و
`domain/catalog/services/<service-id>.json`

للمخططات:
`domain/schemas/<service-id>/`

للاختبارات:
`tests/providers/<provider-id>/`
و
`tests/services/<service-id>/`

إذا لم تكن هذه المجلدات موجودة بعد، تُنشأ عند بدء مرحلة الانتقال المناسبة، ولا يُفرض نقل المشروع الحالي إليها دفعة واحدة.

## 4. عقد الموصل (Provider Adapter)

كل موصل يلتزم بالعمليات المنطقية التالية:
- `getCapabilities()`: المنتجات والتغطية والقيود.
- `fetch(query)`: جلب البيانات والتحقق الأولي من استجابة المصدر.
- `normalize(raw)`: تحويل الحقول إلى العقد الموحد.
- `healthCheck()`: فحص محدود لحالة المصدر، إن كان مسموحاً.
- `getAttribution()`: إرجاع نص الإسناد والرابط والترخيص.

لا يُسمح للموصل أن يقرر شكل الواجهة أو أن يكتب HTML. لا يغير الوحدات أو الدقة بصمت، ولا يضع مفاتيح سرية في كود العميل.

## 5. عقد الاستجابة الموحد

مثال توضيحي غير مرتبط بمصدر حقيقي:

```json
{
  "schema_version": "1.0.0",
  "service_id": "weather",
  "provider_id": "example-provider",
  "product_id": "current-conditions",
  "status": "available",
  "retrieved_at": "2026-01-01T10:00:00Z",
  "valid_time": "2026-01-01T10:00:00Z",
  "location": {
    "id": "riyadh",
    "latitude": 24.7136,
    "longitude": 46.6753
  },
  "measurements": [
    {
      "name": "temperature",
      "value": 25.4,
      "unit": "degC",
      "quality_flags": []
    }
  ],
  "provenance": {
    "source_url": "https://example.invalid/api",
    "license_status": "research_only",
    "attribution": "Example provider",
    "methodology": "Provider-reported model output",
    "limitations": ["Illustrative example only"]
  }
}
```

- استخدم `valid_time` أو حقولاً زمنية أكثر تحديداً لتمييز الرصد من التوقع.
- لا تستخدم القيمة صفر لتمثيل غياب القياس.
- حافظ على القيم الأصلية ووحداتها في سجلات المصدر عند الحاجة، وسجل التحويل الذي أجريته.
- لا تخلط بيانات منتجات مختلفة في سلسلة واحدة دون بيان واضح.

## 6. التعامل مع الأعطال

- `401/403`: خطأ مصادقة أو صلاحية؛ لا تكرر الطلب بلا نهاية.
- `404`: المنتج أو المسار غير موجود؛ سجل التشخيص.
- `429`: احترم `Retry-After` وحدود المزود مع تراجع تدريجي.
- `5xx` أو timeout: عدد محدود من المحاولات ثم حالة unavailable.
- استجابة ناقصة أو مخطط متغير: ارفض البيانات غير المتوافقة ولا تعرض قيماً مختلقة.
- مصدر احتياطي: لا يستخدم إلا إذا كان معتمداً ومناسباً للغرض، مع إظهار المصدر البديل والمنهجية.

## 7. الحد الأدنى للاختبارات

1. عينة ناجحة معروفة.
2. حقول ناقصة أو أنواع بيانات خاطئة.
3. قيمة مفقودة وnodata وNaN والقيم خارج النطاق.
4. وحدات وتحويلات صحيحة.
5. اختلاف التوقيت والتواريخ.
6. أخطاء 401 و403 و404 و429 و5xx والمهلة.
7. احترام حدود الطلب وعدم تكرار الاتصال بلا داعٍ.
8. إثبات أن الواجهة تعرض اسم المصدر وتاريخ البيانات والقيود.
9. اختبار عدم تسرب المفاتيح والأسرار.

الاختبارات الوحدوية تستخدم fixtures ولا تعتمد على الإنترنت. الاختبار الحي منفصل ومحدود.

## 8. نموذج سجل مصدر

انسخ النموذج التالي لكل مصدر جديد، ثم املأه بالمعلومات التي تم التحقق منها:

| الحقل | القيمة |
|---|---|
| provider_id | معرف ثابت بحروف صغيرة |
| الاسم والجهة المالكة | — |
| الرابط الرسمي | — |
| الخدمة والمنتجات | — |
| الترخيص وقرار إعادة العرض | — |
| الإسناد | — |
| التغطية والدقة | — |
| التأخر وتواتر التحديث | — |
| المصادقة وحدود الطلب | — |
| التكلفة | — |
| حالة الاعتماد | research_only افتراضياً حتى المراجعة |
| تاريخ آخر تحقق | — |

## 9. قائمة قبول PR

- [ ] مصدر رسمي موثق.
- [ ] الترخيص وحقوق العرض وإعادة الاستخدام واضحة.
- [ ] الموصل مستقل عن الواجهة.
- [ ] التحويل إلى العقد الموحد موثق.
- [ ] الوحدات والتوقيت والدقة محفوظة.
- [ ] الإسناد والقيود تظهر للمستخدم.
- [ ] اختبارات fixtures ناجحة.
- [ ] اختبار حي محدود عند الحاجة.
- [ ] لا أسرار في المستودع أو العميل.
- [ ] لا تأثير جانبي على الخدمات الحالية.
- [ ] الوثائق والكتالوج وخارطة الطريق محدثة.
